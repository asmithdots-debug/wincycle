# WinCycle

Маленькая нативная утилита для macOS: переключение между окнами на переднем плане через Option+Tab + подсветка активного окна с затемнением остальных.

## Зачем

На Command+Tab в macOS переключаются программы, а не окна — если у одного приложения открыто несколько окон, между ними так нельзя перемещаться. Стандартный обходной путь — Mission Control или сторонние переключатели со списком миниатюр на экране. Если открыто несколько окон на одном экране, то стандартными методами между ними неудобно переключаться.

Так же и с подсветкой активного окна: в macOS такой настройки нет вовсе, а сторонние решения либо платные, либо ненадёжные, либо тянут за собой лишние возможности, которые не нужны.

WinCycle делает эти вещи сам, без внешних зависимостей — плюс раскладывает окна по экрану, чтобы не приходилось каждое новое окно пристраивать вручную.

## Что умеет

**Переключение окон**
- `Option + Tab` — следующее окно (часовой стрелке)
- `Option + Shift + Tab` — предыдущее окно (против часовой)
- `Option + Command + Tab` — поменять активное окно местами со следующим по тому же кругу
- `Option + Command + Shift + Tab` — с предыдущим

Обход идёт не по истории переключений (как у Command+Tab), а по кругу на экране: окна сортируются по углу вокруг их общего центра, поэтому движение ощущается предсказуемо — слева направо, сверху вниз, по кругу.

Порядок фиксируется один раз при первом нажатии Tab и держится до отпускания Option — список не пересортировывается на лету.

Из перебора исключены:
- свёрнутые окна;
- окна программ, спрятанных через Command+H;
- панели, диалоги и прочие нестандартные окна — только обычные окна программ;
- окна в настоящем системном полноэкранном режиме — они живут на отдельном рабочем столе, переключаться на них через Tab всё равно не выйдет.

Просто большое окно из перебора не исключается: отличить «человек развернул его специально» от «оно открылось таким» по одному размеру нельзя, и попытки угадывать это по площади уже дважды ломали раскладку — подробности в [DESIGN.md](DESIGN.md).

**Раскладка окон**

Новое окно само встраивается к уже открытым на том же экране — настоящим деревом разбиений, как в i3, bspwm или в dwindle-режиме Hyprland под капотом. Первое окно занимает экран целиком, каждое следующее делит пополам ячейку **активного** окна — там, где человек как раз работает, а не произвольную последнюю. Зазор между окнами и по краю экрана — 8pt, такой же, как у Raycast Window Management.

- Ячеек максимум пять. Шестое и следующие окна складываются стопкой в последнюю, самую маленькую ячейку — сверху самое новое, до остальных можно добраться перебором.
- Закрытие, сворачивание и Command+H тоже пересчитывают раскладку — освободившееся место сразу отдаётся соседям.
- Если окно переставить самому, клавишами через любой менеджер окон, раскладка это подхватит: окно займёт ту ячейку, куда его положили, а всё остальное каскадом сдвинется по спирали. Если окно вместо этого ужать внутри своей же ячейки (например, было одно на всю половину экрана, стало занимать только четверть) — освободившийся кусок становится настоящей свободной ячейкой: её займёт следующее новое окно или следующая перестановка.
- Окно, развёрнутое почти на весь экран вручную, временно выводится из раскладки; вернули обычный размер — само возвращается.
- Окна, которым нельзя менять размер (настройки системы, настройки программ через Command+,), в раскладку не берутся — они ставятся по центру экрана поверх остальных.

Раскладку можно выключить в меню в строке меню.

**Подсветка активного окна**

Затемняет все окна, кроме активного — прямая замена платным приложениям вроде HazeOver. Включается и настраивается через значок в строке меню:
- вкл/выкл;
- сила затемнения, шесть уровней от 15% до 70%.

## Разрешения

Только **«Универсальный доступ»** (Accessibility) — без него приложение не сможет поднимать окна на передний план. «Запись экрана» не нужна вообще: список окон и их геометрия берутся из публичного API `CGWindowListCopyWindowInfo`, который для этого никаких дополнительных прав не требует.

## Установка

Готовых сборок пока нет — только исходники, ставится через компилятор Swift, который уже стоит в macOS вместе с Command Line Tools (полноценный Xcode не нужен).

```sh
git clone https://github.com/<your-username>/wincycle.git
cd wincycle
./setup-signing.sh   # один раз — создаёт постоянный сертификат для подписи
./build.sh           # собирает, подписывает, устанавливает в ~/Applications, запускает
```

При первом запуске macOS попросит разрешение в **Системные настройки → Конфиденциальность и безопасность → Универсальный доступ**.

### Про постоянную подпись

`setup-signing.sh` создаёт самоподписанный сертификат в отдельной связке ключей (`~/Library/Keychains/wincycle.keychain-db`) и добавляет его в доверенные без пароля администратора. Это не для важности — это чтобы `codesign -s -` не менял отпечаток подписи при каждой пересборке.

Разрешение «Универсальный доступ» в macOS привязано именно к отпечатку подписи. Если подписывать «на лету», каждая правка кода меняет отпечаток, система считает приложение новым, и разрешение приходится выдавать заново — причём одного включения галочки уже недостаточно, нужен `tccutil reset Accessibility local.wincycle` и повторная выдача с нуля. С постоянным сертификатом отпечаток не меняется, и разрешение переживает любые пересборки. Запустите `setup-signing.sh` один раз, `build.sh` — сколько угодно.

### Автозапуск

```sh
cat > ~/Library/LaunchAgents/local.wincycle.plist <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
	<key>Label</key>
	<string>local.wincycle</string>
	<key>ProgramArguments</key>
	<array>
		<string>/Users/YOUR_USERNAME/Applications/WinCycle.app/Contents/MacOS/WinCycle</string>
	</array>
	<key>RunAtLoad</key>
	<true/>
	<key>KeepAlive</key>
	<false/>
</dict>
</plist>
EOF
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.wincycle.plist
```

## Устройство

Один файл, `main.swift`, без зависимостей за пределами AppKit и Carbon (последний нужен только ради `RegisterEventHotKey` — единственный способ повесить системную горячую клавишу без перехвата всего ввода).

- **Список окон и их порядок** — `CGWindowListCopyWindowInfo`.
- **Активация окна** — Accessibility API (`AXUIElementPerformAction` с `kAXRaiseAction`).
- **Подсветка** — прозрачные окна-подложки над каждым экраном, которые переставляются сразу под активное окно (`order(.below, relativeTo:)`); отслеживание смены фокуса — уведомление `NSWorkspace.didActivateApplicationNotification` плюс опрос раз в треть секунды (уведомление не ловит переключение между окнами одной и той же программы).
- **Смена активного окна на лету** — при переключении подложка двигается сразу, не дожидаясь опроса, иначе на треть секунды затемнённым оказывалось бы как раз то окно, на которое переключились.
- **Защита от двух копий** — при старте приложение проверяет, не запущена ли уже другая копия, и выходит, если да. Актуально, если поднимать его и вручную, и службой автозапуска: два перехватчика одной горячей клавиши сбивали бы перебор.

- **Раскладка** — тот же опрос раз в треть секунды сравнивает фактические рамки окон с теми, что раскладка сама им поставила, и по расхождению понимает, что окно подвинули без неё.

Никаких приватных или недокументированных API — только то, что публично в заголовках AppKit/CoreGraphics/Carbon.

Подробное устройство, схемы, разбор уже допущенных ошибок и порядок проверки изменений — в **[DESIGN.md](DESIGN.md)**. Читать перед тем, как что-то менять.
		
## Ограничения

- Только macOS. Собрано и обкатано на macOS 26/27 (Tahoe/бета), минимальная версия в `Info.plist` — 13.0, но на более старых версиях не проверялось.
- Несколько мониторов поддерживаются (подложка создаётся под каждый `NSScreen`), но обкатано на связке из одного экрана.
